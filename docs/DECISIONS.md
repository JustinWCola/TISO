## 实现取舍

- 后端 Web 应用使用 FastAPI。六边形算法使用 Shapely，均匀方格对照使用 NumPy、ContourPy 和 Shapely。
- 距离计算沿用局部米制近似。默认先采目的地附近两圈，再沿六边形六个方向以两倍间距探测，按耗时和缺测情况决定何处补采。已连续超时的方向跳过一圈后复查。孤立可达区若落在探测点之间，仍可能漏绘。预算耗尽或外缘有缺测时可能得到部分结果。显式指定半径的历史请求仍使用圆形裁剪。含无效节点的单元保持空白。
- 产品使用高德底图、地点搜索和算路，测试使用固定合成场及替身 HTTP 响应。当前目的地可通过点击、拖动标记、坐标输入或搜索选择。
- 高德适配器通过替身 HTTP 响应验证方向和顺序恢复。使用授权账号曾验证底图、地点搜索，以及一次反向批量请求返回 20 个有效起点。P2 对比使用离线数据。
- 默认单进程、单任务。实时样本保留在内存中，历史等时圈和用户启用的日程保存在本地 SQLite。日程与手动任务共用队列和算路预算。Compose 只绑定回环，公网认证与 HTTPS 由部署方提供。

## P3 综合公交原型记录

- 到达时间须包含时区且精确到分钟。出发候选统一换算为北京时间后发送，日期随候选时刻跨日。对最长耗时窗口均匀取 4 个候选，向上取整到分钟。从最晚候选逐个检查，首次按时到达即采用其提前量。可行性可能随班次变化，候选之间的短可行窗口可能漏检。目标点保持 0。无可行候选、请求失败和缺测的点保持空耗时。
- 复用自适应六边形网格和队列，公交采用 2 公里粗采样、1 公里最小间距、30 公里自动半径上限、64 点上限和 120 次请求上限。估算按每点 4 次基础查询计算，运行时重试与候选查询共享同一硬预算。高德城市编码由用户提供，起终点使用同一码，跨市边界未自动识别。
- 公交结果显示为近似估算。本地真实请求已对比白天和午夜前后同一对起终点的返回。日期和时间的排班语义、首末班车、跨日换乘与等车耗时仍待进一步核对，见 [API 验证记录](API_VALIDATION.md)。
- 离线验收通过。后端 `uv run --locked python -m pytest -q` 通过 41 项，前端 `npm test` 通过 2 项，`npm run build` 成功。Chromium 使用本地生产构建和替身算路响应，通过了驾车与公交表单、预算估算、结果图例和地图交互的端到端检查。

## P3 高德在线地铁原型

- 逆地理编码返回城市编码，附近地铁 POI 提供线路线索，高德线路查询补全上游站点顺序，站点详情继续发现换乘线路。这些查询与站到站算路共用 120 次请求上限。只使用高德地铁图策略返回的地铁及步行方案。
- 从最多两个候选下车站沿入站方向倒查。每对站点最多检查两个出发时刻。两个时刻均实测耗时超限后，剪掉该线路方向上的普通站，保留已知换乘站供独立判断。查询失败、无路线或未完整探查的换乘可能遗漏可达站，结果为近似估计。
- 先扣除下车后步行时间，再将起乘站剩余时间按 1.2 米/秒换算成直线步行范围。各阈值取站点范围并集，相邻阈值相减生成不重叠色带。步行范围以车站坐标为中心，受大陆陆地范围和分析半径裁剪。
- 地铁版离线验收通过。后端 40 项，前端 2 项，生产构建及本地 Chromium 端到端均通过，覆盖自动城市编码、线路剪枝、换乘保留和空色带阈值。

## P3 地铁本地路网

- 上海随附 OpenStreetMap 快照，城市边界关系为 `913067`，数据快照为 2026-11-26 16:09 北京时间。包含 18 条编号线路、412 个站、1,180 条有向乘车边和 3,512 条有向换乘边。运行时间以站间距离、停站开销和合理的整条线路时长估算。不同线路换乘增加 180 秒和平台间直线步行，换到同线路的另一方向或班型增加 120 秒和平台间步行。初始候车估算 120 秒。
- 对目的地附近最多三个站计算出站步行时间，从这些站反向求最短路。乘车和换乘以路线方向和班型建图，跨班型需要换乘。最短路在最长时长内停止，站外步行按 1.2 米/秒画近似范围。本地路网生成后按城市边界命中，分析请求无需线路 API 或地理编码。
- 用户显式生成时，Overpass 先按目的地坐标定位行政关系，再下载地铁关系和边界，生成体积较小的压缩 JSON 并原子写入设置卷。城市边界及站点从 WGS-84 近似转换到基图使用的 GCJ-02。不同名的相连车站有可能缺失换乘，耗时估计不包含实际排班。原型实测数据仅作验证记录。[OpenStreetMap 版权及许可](https://www.openstreetmap.org/copyright) · [高德开放平台服务协议](https://developer.amap.com/pages/terms/)
- 本地部署版用上海人民广场验证了 30 和 120 分钟等时圈，算路请求均为零。后端 35 项、前端 2 项、生产构建和 Chromium 端到端验收通过。新城市生成和重启后复用已用离线样本验收，真实北京样例受公开 Overpass 服务超时阻塞。[API 验证记录](API_VALIDATION.md)
- 地铁等时圈在每个阈值合并目的地的直接步行范围与乘车后的站点步行范围。目的地的耗时为零，即使附近没有可用车站，也会绘制直接步行色带。
- 地铁出图在生成色带前按 5 米容差简化轮廓并保留拓扑。上海人民广场默认步速、120 分钟范围、5 分钟分档的结果由约 37.8 万个坐标点减至 15.3 万个，未压缩 JSON 由 14.9 MB 降至 6.1 MB。地图复用已投影的地铁路径，拖动时更新视口变换，静止时跳过重复重绘。JSON 响应按客户端支持情况启用 gzip。

## 算路范围数据

- `backend/app/core/data/mainland_gcj02.wkb.gz` 保存一个有效的 GCJ‑02 MultiPolygon，含 63 个闭环组成部分。WGS‑84 原始数据使用 Natural Earth 1:10m v5.1.1 的 `ne_10m_admin_0_map_units` 和 `ne_10m_ocean`。选择 `GU_A3=CHN`，去掉海洋以及港澳台单元，再对边界线段以 0.01° 上限加密、以 coordtransform 转成 GCJ‑02 并保留六位小数。海南和来源覆盖的沿海岛屿保留。[Natural Earth 行政单元](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/) · [海洋多边形](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-ocean/) · [坐标转换](https://github.com/wandergis/coordtransform)
- 多边形约束高德驾车请求的范围和结果绘制。输入按与高德一致的六位小数检查严格内部。多边形是小比例尺数据，填海新区、窄水道和贴岸位置仍受源数据精度影响。用于算路范围筛选。

## P2 离线基准

合批与位置误差加密上线前后，用 15 分钟阈值和 500 米最小间距对照了三个合成场。平滑场由 29 批降至 27 批，快速通道为 52 批，孤立可达区为 15 批。三组对解析轮廓的最大双向偏差取整后分别为 5、95、26 米，与原策略持平。另有合批回归验证一组内侧补采和外圈探测由两批合为一批。位置误差和请求节省仍需真实路况验证。
