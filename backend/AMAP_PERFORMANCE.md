# TISO 高德距离测量性能报告

2026-11-27。使用相同的 570 个模拟算路点，100 点/批、3 QPS、3 个在途请求的配置将 HTTP 请求从 30 次降到 7 次，后端端到端计算耗时从 30.058 秒降到 4.243 秒。四组对照的样本耗时、等时线和填色带输出一致。本次真实高德配额消耗为 0。

## 接口与账户核验

- 高德 `GET /v3/distance` 的 `origins` 支持最多 100 对坐标。驾车使用 `type=1`，TISO 将采样点作为起点，并传入同一个目的地。项目阶段记录记载，曾有一个授权账户的反向批量请求返回 20 个有效起点。该记录确认了当时账户能使用距离测量及至少 20 点/批，当前 Key 的账户档位、100 点批上限和实际限速仍待授权核验。[距离测量接口](https://lbs.amap.com/api/webservice/guide/api/direction/)
- 高德以每秒调用次数标示距离测量 QPS，未认证、个人认证、企业乘风计划和企业技术服务许可档分别列为 0、3、30 和 100。公开说明未给出时间窗口细节。高德购买的服务 QPS 包由同一账户下的 Key 共享，TISO 在单后端进程的事件循环内按 Key 等间隔发出请求，调高单 Key 配置前需结合账户的其他用量。[基础服务计费](https://lbs.amap.com/pages/base_service_price) [QPS 超限说明](https://lbs.amap.com/faq/quota-key/key/41207) [服务升级](https://lbs.amap.com/upgrade)
- 高德将距离测量列入基础 LBS 月配额。公开计费说明与历史记录均未给出该接口的批量扣额单位。实际按 HTTP 批次、按起终点对，或如何计入部分失败与重试，仍需用授权账户对照控制台用量确认。[基础服务计费](https://lbs.amap.com/pages/base_service_price)

## Mock 基准结果

对同一个上海人民广场驾车任务运行优化前的 `f4a9922` 与当前版本。固定半径 6 公里，最长耗时 45 分钟，初始间距 1 公里，单个 Mock HTTP 响应延迟 700 毫秒。使用真实任务执行器、六边形规划和几何生成流程，由 `httpx.MockTransport` 返回确定性耗时。每个配置测量一次，实验未注入失败或重试。

| 指标 | 优化前 20 / 1 / 1 | 优化后 20 / 3 / 3 | 优化后 100 / 3 / 1 | 优化后 100 / 3 / 3 |
| --- | ---: | ---: | ---: | ---: |
| HTTP 请求次数 | 30 | 30 | 7 | 7 |
| 算路点数 | 570 | 570 | 570 | 570 |
| 平均每请求算路点数 | 19.00 | 19.00 | 81.43 | 81.43 |
| 批次填充率 | 95.00% | 95.00% | 81.43% | 81.43% |
| 在途请求峰值 | 1 | 3 | 1 | 3 |
| 首次发请求至最后一次响应（秒） | 29.764 | 11.651 | 5.055 | 3.940 |
| 算路窗口吞吐（点/秒） | 19.15 | 48.92 | 112.75 | 144.68 |
| 后端端到端计算耗时（秒） | 30.058 | 11.954 | 5.359 | 4.243 |
| 真实高德配额消耗 | 0 | 0 | 0 | 0 |

HTTP 请求计数包含实际发起的尝试，运行时重试也占用任务请求预算。算路点数统计去重后提交的起点，本实验的 570 个起点均有有效响应。目的地点以零耗时计入样本，因此样本总数为 571。填充率为提交起点总数除以 HTTP 请求数与每批上限的乘积。每轮末尾可发一个未满批次，100 点配置虽然填充率下降，单请求平均处理点数仍增至 4.29 倍。

端到端计算时间从后端创建任务到任务结束，包含采样、批次间等待、Mock 响应以及预览和最终几何构建。100 / 3 / 3 比旧版端到端提速约 7.1 倍，减少 76.7% 的 HTTP 请求。这些数字描述固定延迟的 Mock 场景。线上耗时随高德响应、当前路况和重试而变化。

## 配置与复现

默认配置为 `AMAP_BATCH_SIZE=20`、`AMAP_QPS=1`、`AMAP_MAX_CONCURRENCY=1`。批大小允许 1 至 100，另外两项为正整数。同一 Key 的手动任务、定时任务及重试共用发送速率、在途上限和限流冷却。每轮先去重、过滤范围外起点，再用有界并发发送，同一轮收尾后才规划下一轮。任务仍按现有规则串行接纳。

在 `backend` 运行以下离线命令。对旧版复测时，将同一个 `scripts/benchmark_amap.py` 放入 `f4a9922` 的独立检出目录，按旧版固定的 20 / 1 / 1 执行。

```sh
AMAP_BATCH_SIZE=100 AMAP_QPS=3 AMAP_MAX_CONCURRENCY=3 uv run --locked python -m scripts.benchmark_amap
```

输出单独报告 HTTP 次数、去重算路点和含重试提交点数、填充率、后端端到端耗时及真实配额用量。四组样本与几何的 SHA-256 均为 `53fab9fea8e4899d54018d508051965e71463b88d784eefb75e56f8987ceac39`。

在 20 点/批条件下对比旧版与新版的 `scripts.benchmark_sampling`，各向异性、快速走廊和障碍三组场景的平均误差、P90 误差、等时面 IoU、覆盖率、样本数和批次数均一致。

## 本地真实任务观察

2026-11-27，本机完成一次 30 分钟等时圈的驾车任务。任务用时 12.448 秒，发起 31 次 HTTP 请求，包含 30 个算路批次和 1 次重试。30 批返回全部 1,912 个算路点，平均每批 63.73 点，含 9 个 100 点满批。按成功响应的时间排列，每批点数如下。

```text
18, 12, 18, 24, 30, 36, 42, 48, 54, 60
65, 67, 70, 65, 62, 65, 42, 22, 56, 100
100, 100, 100, 100, 100, 76, 100, 100, 80, 100
```

连续 6 个满批响应的首尾相差 1.653 秒，与本地 3 QPS 配置一致。本次任务的内存样本记录的是响应观测时间，逐次发送间隔和重试点数无法从本次记录还原。新任务在结果中保存每次发起 HTTP 请求的批号、尝试序号、起点数和发送时间。真实高德配额扣减尚未读数。

任务达到 250 米局部最小网格间距，完成 3 轮加密，覆盖率 99.55%。采样总数达到当时的 2,000 点上限，其中包含零耗时目标点和 87 个大陆陆地范围外的点。请求预算为 150 次。本机新建驾车任务配置为 20,000 点、300 次 HTTP 请求。
